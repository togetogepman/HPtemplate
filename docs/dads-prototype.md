# DADSを利用した研究室HPテンプレート試作

## 1. 目的

この試作は、既存の研究室HPテンプレートが持つ情報項目を維持しながら、デジタル庁デザインシステム（DADS）の設計思想を適用した比較用デザインです。情報の見つけやすさ、読みやすさ、操作状態の明確さ、アクセシビリティ、長期運用時の壊れにくさを評価するために作成しています。

実装時に確認した公式資料はDADS v2.16.0です。

## 2. DADSから採用した設計原則

- 見出し、説明、一覧の関係を明確にする情報階層
- 8pxを基準にした一貫した余白スケール
- 1カラムを基本とし、内容に応じて2列・3列へ分割するレスポンシブレイアウト
- 本文と背景、UI境界と背景のコントラストへの配慮
- 青色と下線を併用し、目的が分かる文言を使うリンク
- 48pxを基本とするボタンと44×44 CSS px以上の操作領域
- 黄色背景と黒い外枠を組み合わせた明確なフォーカス表示
- NEWSと業績を走査しやすいリソースリストとして表現
- プロフィール項目を意味的な説明リストとして表現
- JavaScriptに依存せず主要情報へ到達できる段階的拡張

## 3. 既存テンプレートから変更した点

- PCの左固定ナビゲーションを、上部の水平ナビゲーションへ変更
- モバイルのドロワーを、ページ幅全体の開閉式メニューへ簡素化
- 画像全面表示のメインビジュアルを、紹介文と画像の2分割へ変更
- NEWSを日付、カテゴリー、タイトルからなるリソースリストへ変更
- 研究テーマを画像、領域、見出し、説明、導線を持つカードへ変更
- モットーを枠付きカードから番号付きステートメントへ変更
- メンバーを所属・課程別の意味的な一覧へ変更
- プロフィールを説明リストと年別履歴へ変更
- 論文・研究発表からSwiperとタブを廃止し、通常見出しと年別一覧へ変更
- Contactを研究室参加、共同研究、問い合わせ、所在地、アクセスに分割
- Google Fontsへの外部依存を廃止し、日本語システムフォントを使用
- 件数に応じた「もっと見る」を廃止し、重要情報を初期表示

## 5. DADSそのものを複製していない点

この試作はDADSのトークンをそのまま配布したものでも、デジタル庁のサイトを模倣したものでもありません。研究室サイトの情報量と編集方法に合わせて、色、コンテンツ幅、カード構造、見出し、文章、ナビゲーションを独自に構成しています。

デジタル庁のロゴ、政府機関の名称、公式サイトと誤認させる表示は含みません。「DADS準拠」「デジタル庁公式テンプレート」とも表示しません。

## 6. サンプルデータの扱い

`index.html`は利用者が置換する明示的なプレースホルダーだけを掲載しています。`sample.html`は表示確認用であり、人物名、所属、研究テーマ、業績、日付は「サンプル」または「架空サンプル」と明記しています。

連絡先は`contact@example.ac.jp`、住所は`〒000-0000 ○○県○○市○○`を使用し、例示用ダミーと明記しています。実在する人物、研究室、論文、賞、研究費、共同研究先、顧客情報は追加していません。

既存のサンプル画像を継続使用しています。公開時は、画像の内容、権利、alt、人物の掲載許可を利用者が確認して差し替える必要があります。

## 7. 既知の制約

- 単一ページの静的テンプレートであり、CMS、検索、問い合わせ送信、認証、データベースはありません。
- モバイルメニューとメールコピー以外はJavaScriptを使用しません。
- Clipboard APIはブラウザの権限や実行環境により失敗する場合があります。限定的なfallback後も失敗した場合は手動コピーを案内します。
- 地図、外部プロフィール、Google Scholar等のリンクは、正しいURLが提供されるまで設定しません。
- DADS本体とコードスニペットは更新されるため、将来のDADSバージョンとの一致を自動では保証しません。
- `library.js`とSwiper CSSは既存用途の調査可能性を残すためファイルを削除していませんが、DADS版ページからは読み込みません。

## 8. 次に検討すべき事項

- 実際の研究室情報を用いた情報量と見出し順の評価
- プライマリーカラー変更時の全組み合わせのコントラスト再確認
- 支援技術による読み上げ確認
- 実機のiOS／Androidでのメニュー、コピー、フォーカス表示の確認
- 外部リンク、PDF、研究者情報へ適切なリンク種別表示を追加
- 画像の著作権、肖像権、掲載許可、altの最終確認
- DADS更新時に採用方針を再評価する運用ルール

## 9. 現行版とDADS版を比較する評価観点

| 評価観点 | 確認する内容 |
|---|---|
| 情報の見つけやすさ | 初見の利用者がNEWS、研究、メンバー、業績、Contactへ迷わず到達できるか |
| 読みやすさ | 長い研究テーマ、経歴、論文情報を無理なく読めるか |
| 操作の明確さ | リンクとボタン、hoverとfocus、内部リンクと外部リンクを区別できるか |
| モバイル | 375pxで横スクロールなく、メニューと主要導線を操作できるか |
| キーボード | スキップリンク、メニュー、本文リンク、コピー、detailsを順序どおり操作できるか |
| 情報の完全性 | JavaScript無効時や0件時にも必要な情報と案内が残るか |
| 編集しやすさ | 非エンジニアがHTML内のプレースホルダーを見つけ、項目を追加・削除できるか |
| 継続運用 | 件数増加、長文、空カテゴリー、セクション削除でレイアウトや操作が壊れないか |
| ブランド調整 | `theme.css`の色トークン変更を中心に研究室ごとの印象を変えられるか |
| 事実性と安全性 | 公開前に事実、個人情報、画像権利、帰属表示を確認できる構造か |
