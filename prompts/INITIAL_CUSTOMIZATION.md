# 入力済みExcelから初回カスタマイズを行う

このファイルは、研究室情報を入力するフォームではありません。リポジトリ内の `input/laboratory-input.xlsx` と `input/images/` を入力の正本として、Codexへ初回カスタマイズを依頼するための文書です。

利用者は次の操作だけを行ってください。

1. `input/laboratory-input.xlsx` をそのまま開き、各シートの黄色い入力欄を書き換える
2. 使用する画像を `input/images/` へ入れ、Excelの画像欄へファイル名を入力する
3. `00_チェック`が「入力完了」になったことを確認してExcelを保存する
4. Codexでこのリポジトリを開き、このファイル全体を渡す

メイン画像は必須です。研究テーマ画像、プロフィール画像、大学・組織ロゴ、SNS共有画像（OGP）、サイトアイコンは任意です。画像の推奨サイズ・形式はExcel内に記載しています。

Excelと`input/images/`はリポジトリの一部で、commit・pushするとGitHubへ保存される可能性があります。公開されても問題ない情報・画像だけを入力してください。

## Codexへの依頼

`input/laboratory-input.xlsx` と `input/images/` を読み取り、`index.html` を初回カスタマイズしてください。

### 1. 作業前確認

1. `AGENTS.md`、`DESIGN.md`、`LICENSE.md`を全文読み、すべての指示に従ってください。
2. 現在のディレクトリ、branch、HEAD、working tree、upstream、remoteとの差分を確認してください。remoteを利用するため、最初にfetchしてください。
3. 既存の未コミット変更を、修正・破棄・stash・reset・checkout・rebase・commitしないでください。今回の変更と分離できない場合は、編集を開始せず理由を報告してください。
4. `sample.html`は完成見本・回帰試験用なので編集しないでください。公開用ページの正本は`index.html`です。
5. Excelと`input/images/`は移動、リネーム、再作成、`.gitignore`への追加をせず、現在のファイルを入力の正本として扱ってください。

### 2. `00_チェック`を先に確認する

1. 最初に`00_チェック`の全体判定と各シートの状態を確認してください。
2. 全体判定が「入力未完了」の場合は、判定式だけを盲信せず入力内容も確認し、サンプルのままの必須情報や未入力箇所をシート名・項目名付きで報告してください。
3. 入力未完了のサンプル情報を`index.html`へ流し込まず、初回反映を停止してください。
4. 意図的に「いいえ」としたセクション、明示的に表示しない分類、完全に空の予備行、任意画像の「いいえ」はエラー扱いしないでください。
5. 追加行には判定式がない場合があります。`00_チェック`が完了していても、見出しと入力内容から追加行の完全性を別途確認してください。
6. `10_画像`のメイン画像が未入力の場合は初回反映を停止してください。

### 3. Excelの読み取り規則

- セル番地だけに依存せず、シート名、表題、列見出し、`このセクションを表示する`、`セクション名`、`判定`、データ行の意味を優先して読んでください。
- 黄色いセルかどうかだけで入力データを判定しないでください。
- 空欄の予備行はHTMLへ出力しないでください。用意済みの行数を上限にせず、利用者が追加した行も見出しと内容から読み取ってください。
- `No.`は入力管理用です。現在のHTMLで番号表示が必要な項目を除き、公開ページへ出さないでください。
- 一部だけ入力された追加行は推測で補完せず、シート名・行・不足項目を報告してください。
- 入力資料にない研究内容、人物、所属、肩書、経歴、受賞、論文、共同研究先、連絡先、URL等を創作しないでください。

### 4. 画像ファイルの共通規則

1. Excelで指定された画像ファイル名は、`input/images/`で大文字・小文字と拡張子を含めて完全一致確認してください。
2. `使用する=はい`または必須の画像についてファイルが存在しない場合は、シート名・項目・ファイル名を報告して反映を停止してください。似た名前のファイルを勝手に採用しないでください。
3. 指定されていない画像を生成、Web検索、転載、別画像で代替しないでください。
4. `input/images/`の原本は破壊的に上書き、削除、移動しないでください。公開用画像は原則として`assets/images/user/`へコピーしてください。
5. 公開用ファイル名は、用途が分かる安全な英数字名へ整理して構いません。拡張子は原則として元画像を維持してください。
6. `input/images/`内の未使用画像は無視し、自動削除しないでください。
7. 画像が極端に大きい、非対応形式、破損等でそのまま公開するのが不適切な場合は、勝手に別形式へ変換せず、処理可否と対応案を報告してください。
8. 画像・ロゴの掲載許可、著作権、肖像権、組織の利用規程は自動判断せず、利用者確認事項として報告してください。

### 5. シート別の反映規則

#### `01_基本情報`

- ページタイトル、検索結果の説明、研究室名（日本語・英語）を反映してください。
- `<title>`、description、OGP等、現行HTML内で同じ内容を使う関連メタ情報は、既存構造を確認して矛盾しないよう更新してください。
- Excelにない公開予定URLやOGP画像URLを利用者へ追加要求せず、入力にないURLを創作しないでください。

#### `02_NEWS`から`08_Contact`までのセクション共通

- `このセクションを表示する`が`はい`なら使用し、`いいえ`なら公開用の`index.html`から削除してください。
- 削除時は`section`要素だけを機械的に消さず、左側／ページ内ナビゲーション、現在位置表示、ページ内リンク、タブ、`もっと見る`、Swiper、対象DOMを前提にしたJavaScript等の依存箇所を調査してください。
- セクションを削除しても、残るセクションのナビゲーションやJavaScriptが停止せず、console errorが出ないように調整してください。
- `セクション名`を変更する場合は、ページ見出し、ナビゲーション、現在位置表示等、利用者に見える名称を一貫して変更してください。既存CSS・JavaScriptを壊す不要な`id`変更はしないでください。

#### `02_NEWS`

- `日付`と`本文`がある有効行を反映し、任意の`リンクURL`は入力がある場合だけ使用してください。
- 空の予備行は出力せず、追加行も読み取ってください。

#### `03_研究テーマ`

- `本文①（画像の上）`は画像の上、`本文②（画像の下）`は画像の下に置く文章です。
- `画像を使用する=はい`の場合は、同じ行の`画像ファイル名`と`画像の説明（alt）`を使用してください。画像ファイルは`input/images/`から確認し、公開用コピーを`assets/images/user/`へ配置してください。
- ①と②の両方がある場合は画像を間に配置してください。片方だけの場合は、不自然な空要素を作らず表示してください。
- `画像を使用する=いいえ`の場合は、その研究テーマの`.theme-img`等の画像枠を公開用HTMLへ出力しないでください。`sample-ph-01.png`、`sample-ph-02.png`等のサンプル画像を残さないでください。
- 画像を使う行でaltが空欄の場合は推測で補完せず、不足として報告してください。

#### `04_研究室のモットー`

- `表題`と`本文`がある有効行だけを反映してください。

#### `05_研究室メンバー`

- `区分`、任意の`年度`、`氏名・所属等`を読み、同じ区分・年度のまとまりが既存表示構造と整合するよう反映してください。
- 学生氏名、所属、進路等の掲載許可は自動判断せず、利用者確認が必要な事項として報告してください。

#### `06_プロフィール`

- 肩書、氏名、外部リンクを反映してください。リンク名とURLの片方だけが入力された行は補完せず報告してください。
- `区分`、`年`、`内容`の行は、経歴・受賞歴・所属学会等の区分名を正としてグループ化してください。追加された区分も固定リストに限定せず読み取ってください。

#### `07_論文・研究発表`

- 上部の分類設定を正本としてください。`表示する`が`いいえ`の分類は、タブ、左ナビ内の分類項目、対応する一覧、対象を前提にしたJavaScript処理を必要に応じて削除・調整してください。
- 分類名を変更した場合は、タブ、左ナビ内の分類項目等、利用者に見える名称を一貫して変更してください。
- 分類設定の空欄と明示的な`いいえ`を同一視しないでください。
- 各分類の本文と任意の外部リンクURLを読み、空行は出力しないでください。追加行も分類と内容から読み取ってください。
- 著者、題名、媒体、巻号、年、DOI、URL等を推測で補完しないでください。

#### `08_Contact`

- 募集・問い合わせ文、メールアドレス、郵便番号、住所を反映してください。
- `Google Mapを表示する`が`いいえ`ならMap部分を削除してください。`はい`なら`Google Map埋め込みHTML`の入力を使用してください。
- 入力された内容がGoogle Mapsの埋め込み`iframe`として妥当か確認してください。APIキーを必要とする実装は追加しないでください。
- Excel内の設定手順や説明文、Google Mapsへの案内リンクを公開HTML本文へ出力しないでください。

#### `09_フッター`

- 利用者が変更できるコピーライトはExcel入力に従ってください。
- `Created with`、株式会社アカデメイアのロゴ、`https://www.academeia15.co.jp/web-template`へのリンクは、無料利用条件に従い表示・クリック可能な状態で維持してください。Excel入力を理由に削除、非表示化、URL変更をしないでください。

#### `10_画像`

- `hero_main`（メイン画像）は必須です。`ファイル名`と`画像の説明`を使い、公開用のヒーロー画像へ反映してください。`sample-mv.png`を`index.html`に残さないでください。
- `profile_main`が`はい`ならプロフィール画像を反映してください。画像の説明が空欄の場合は、画像が研究者本人のプロフィール画像であることがExcelと周辺情報から明確な場合に限り、プロフィール氏名をaltに使用できます。`いいえ`ならプロフィール画像設定用プレースホルダーを公開ページへ残さないでください。
- `organization_logo`が`はい`なら大学・組織ロゴを反映し、`画像の説明`をaltに使用してください。`いいえ`なら組織ロゴ設定用プレースホルダーを公開ページへ残さないでください。SVGは不要にPNGへ変換しないでください。
- `ogp_main`（SNS共有画像）が`はい`なら指定画像を`og:image`と`twitter:image`へ反映してください。`いいえ`ならメイン画像を両方へ使用してください。SNS共有画像の説明が空欄なら、専用画像使用時は`研究室名のSNS共有画像`のような事実を追加しない機械的な説明に限って補助できます。メイン画像流用時はメイン画像の説明を使用してください。
- `site_icon`が`はい`なら、指定された正方形PNGを公開用にコピーし、`index.html`のfaviconとApple Touch Iconがその画像を参照するよう更新してください。既定faviconとの参照競合が残らないようにしてください。`いいえ`なら現在の既定サイトアイコンを維持してください。

### 6. 実装と検証

1. 現行デザインを維持し、初回入力の反映に必要なファイルだけを最小限変更してください。CMS、DB、API、認証、フォーム送信、常設依存、Excelパーサーや独立ビルドシステムは追加しないでください。
2. サンプル人物、団体、研究、論文、受賞、住所、メール、仮リンク、`sample-mv.png`、`sample-ph-01.png`、`sample-ph-02.png`、画像設定用プレースホルダー等が`index.html`に残っていないことを確認してください。
3. Excelで`いいえ`にしたセクション・分類・画像枠が残っていないこと、セクション名・分類名が各表示箇所で一致すること、Excel入力と公開情報が明らかに食い違わないことを確認してください。
4. Excelで指定されたすべての使用画像が存在し、`index.html`から参照するローカル画像、CSS、JavaScriptに404がないことを確認してください。
5. 画像のalt、縦横比、PC/SP表示、横方向オーバーフローを確認してください。画像の権利・掲載許可は利用者確認事項として報告してください。
6. HTML/CSS/JavaScriptの静的検査を行ってください。
7. PC幅とスマートフォン幅で文字切れ、重なり、キーボードフォーカス、モバイルメニュー、ナビゲーション、Swiper、タブ、`もっと見る`、Contactのコピーを確認してください。削除した要素がある場合は、残る操作にconsole errorやwarningがないことも確認してください。
8. `index.html`と`sample.html`の帰属表示が表示・クリック可能で、正式URLを指すことを確認してください。

### 7. Gitと最終報告

1. 検証成功後、今回の変更だけをstage・commitし、現在の作業branchをremoteへpushしてください。新規branch、PR、`main`へのmerge、tag作成、branch削除は行わないでください。
2. 最後に日本語で、結論、Excelのパスと認識したシート、画像入力元、反映内容、入力不足・掲載許可等の要確認事項、テスト結果（成功・失敗・未実施・検証不能を区別）、変更ファイル、commit hash、push先、working treeとremoteの同期状態、残課題を報告してください。
